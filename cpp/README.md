# p2proxy v2（C++ 桌面版）

一个程序，两种角色：出口电脑当**服务端**，其他电脑当**客户端**，客户端通过服务端的网络上网。两台电脑之间直接连接（UDP 打洞 + QUIC 加密隧道），不经过任何中转服务器。

- **一个服务端，多个客户端**：同一个密钥只能有一台电脑当服务端，第二台尝试时会被拒绝；客户端数量不限。
- **输入密钥即可连接**：客户端粘贴服务端的密钥，就会自动找到并连上服务端。
- **Clash 订阅**：客户端连上后会给出一个订阅地址，在 Clash 里添加并打开 TUN，所有流量都走服务端；隧道断开时直接断网，不会改走本地网络。
- **测速**：测量客户端到服务端的隧道上下行速度、延迟和丢包。
- **一键更新**：有新版本时界面里点一下即可更新本机；客户端还能远程更新服务端。每个版本都有签名，被篡改的安装包会被拒绝。
- **速度和稳定性**：传输层是微软的 msquic，默认使用 BBR 拥塞控制（可切换为 CUBIC）。服务端重启后客户端约 1 秒内重连，断线 20 秒内判定。本机测试中隧道可达到约 5 Gbps。

## 下载与运行

从 [GitHub Releases](https://github.com/zsdl1288/p2proxy/releases) 下载 `p2proxy-v2.x.x-windows-x64.zip`，解压到一个固定位置。文件夹里的几个 DLL 要和 `p2proxy.exe` 放在一起。

双击 `p2proxy.exe`，第一次会问"这台电脑是哪一端"。系统要求 Windows 10/11 64 位（WebView2 运行库，Windows 11 自带）。

关闭窗口**不会**停止 p2proxy，它会留在任务栏右下角的托盘里，这样服务端不会被误关。要完全退出，请右键托盘图标选择"退出"。

同一台电脑上只会运行一份 p2proxy。已经在运行时再双击 `p2proxy.exe`，会直接把正在运行的窗口调出来，不会启动第二份。

## 服务端（出口电脑）

1. 选"服务端（出口）"。
2. 界面上会显示密钥，点"复制"发给客户端（用安全的方式，密钥就是访问这台电脑网络的钥匙）。
3. 在设置里勾选"开机自动启动"，并在系统设置里关闭睡眠。
4. "已连接的客户端"里可以看到每个客户端的名称、地址、延迟和流量。

如果担心密钥泄露，点"重新生成密钥"，所有客户端都需要输入新密钥。

## 客户端

1. 选"客户端"，粘贴服务端的密钥，点"保存并连接"。
2. 状态变成"已连接"后，复制"Clash 订阅地址"。
3. 打开 **Clash Verge Rev**（或其他 mihomo 内核的 Clash）：
   - "订阅" → 新建 → 粘贴地址 → 保存，并选中这个订阅；
   - 设置里打开**虚拟网卡模式（TUN）**和**严格路由**，关闭 **DNS 覆写**；
   - 模式保持"规则"，不要切换到"直连"。
4. 浏览器打开 https://api.ipify.org ，显示的应该是服务端的 IP。

订阅的规则只有两条：p2proxy 自己连接服务端的流量直连，其余全部走服务端。DNS 使用 fake-ip，域名在服务端解析。

p2proxy 自己的流量（信令、DNS 查询、打洞和隧道）都绑定物理网卡，不经过 Clash 的 TUN，也不依赖 Clash 的规则和 DNS。所以 TUN 开着时退出再打开 p2proxy，也能直接重新连上服务端；在这期间其他程序会断网，连上后恢复。p2proxy 用 DNS-over-HTTPS 解析 ntfy.sh 和 STUN 服务器：先用 Cloudflare（1.1.1.1），连不上时改用阿里 DNS（223.5.5.5）。

## 测速

客户端界面里点"开始测速"，约 20 秒。下载速度通常受服务端的上传带宽限制：A 下载的数据都要从 B 上传过来。

每次测速的结果（下载、上传、延迟、丢包）都会写进**两端**的运行日志：客户端记录自己的结果，服务端记录"某某客户端开始测速"和它报告的结果。在界面底部的"运行日志"或 `%APPDATA%\p2proxy\p2proxy.log` 里都能查到。

## 线路质量与拥塞算法

客户端的状态卡片和服务端的"已连接的客户端"列表会实时显示（按最近 30 秒统计）：

- **延迟 · 抖动**：客户端每 2 秒测一次往返时间；抖动是相邻两次往返时间之差的平均值。测速或下载占满带宽时抖动会明显升高，这反映的是满载时的排队延迟。
- **丢包（两个方向）**：每一端统计自己发出的包有多少丢失，两端每 2 秒交换一次，所以两边都能看到"服务端→客户端"和"客户端→服务端"两个方向。超过 0.5% 显示为黄色，超过 2% 为红色。流量很少时（30 秒内不到 200 个包）显示"流量太少"，因为这时的比例没有意义。

**拥塞算法**在客户端的设置里选择，两个方向都会使用它（服务端会跟随每个客户端的选择）：

- **BBR**（默认）：长距离、高带宽线路上更能跑满速度，但遇到丢包不会主动降速，在会丢包或限速的线路上可能让丢包率偏高。
- **CUBIC**：遇到丢包会降速，速度可能低一些，但在丢包多或被运营商限速的线路上通常更稳。

切换后会自动重连一次。建议在同一时段分别用两种算法跑几次测速，并观察平时上网时的丢包和抖动，再决定用哪种。

## 软件更新

界面下方的"软件更新"会显示当前版本和最新版本。p2proxy 启动后会自动检查一次，之后每 6 小时检查一次，也可以手动点"检查更新"。

- **更新本机**：点"更新到 vX"，下载、校验、替换后自动重启，约断开几秒。
- **远程更新服务端**（客户端界面里）：点服务端那一行的更新按钮，服务端会自己下载新版本并重启，不用去服务端电脑上操作。建议先更新服务端，再更新客户端。
- **客户端不会直连**：客户端检查和下载更新时，由服务端代为从 GitHub 下载，再通过隧道传回来。客户端自己校验签名，服务端无法篡改。
- **安全**：每个版本的校验文件都用发布者的私钥签名（Ed25519），程序内置公钥。安装包被篡改、校验文件被改、拿旧版本冒充新版本，都会被拒绝安装，原来的文件保持不变。
- 程序要放在当前用户有写入权限的文件夹里（不要放在 `C:\Program Files`），否则无法替换文件。
- **v2.2.0 及更早的版本需要手动安装一次 v2.2.1 或更新的版本**：v2.2.1 换了签名密钥，旧版本只认旧密钥，会拒绝一键更新（v2.0.0 本身也没有更新功能）。下载 zip 并解压，右键托盘图标选"退出"，把文件覆盖到原来的文件夹，再打开即可；配置在 `%APPDATA%\p2proxy`，不会丢失。之后就可以一键更新了。

## 已知限制

- **两边都是对称型 NAT 时无法打洞**（例如运营商级 NAT、部分手机热点），也没有中转服务器。服务端界面会提示检测到的 NAT 类型。
- 目前只支持 IPv4 直连。
- Clash 本身退出或崩溃时，系统路由会恢复，可能会直连上网。
- 信令使用免费的 ntfy.sh，每天的消息数有限；连不上时重试会逐渐变慢（最长 5 分钟），服务端上线或网络恢复时会立即重试。

## 命令行参数

| 参数 | 作用 |
|---|---|
| `--minimized` | 启动时只在托盘里运行（开机自启使用） |
| `--profile 名称` | 使用独立的配置目录 `%APPDATA%\p2proxy-名称`，可以在一台电脑上同时运行多份 |
| `--ui-port 端口` | 界面和订阅的本地端口，默认 1090 |
| `--socks-port 端口` | 客户端本地 SOCKS5 端口，默认 1080 |

配置和日志在 `%APPDATA%\p2proxy\`。密钥用 Windows DPAPI 加密保存，只有当前 Windows 用户能解开。

## 从源码编译

需要 Visual Studio 2022（或 Build Tools）的"使用 C++ 的桌面开发"组件，以及 vcpkg：

```
git clone https://github.com/microsoft/vcpkg.git ..\.tools\vcpkg
..\.tools\vcpkg\bootstrap-vcpkg.bat
build.cmd
```

输出在 `build\`：`p2proxy.exe` 和发布签名工具 `p2proxy-sign.exe`。依赖库（msquic、cpp-httplib、nlohmann-json、WebView2、libsodium）由 vcpkg 自动编译。运行时需要把 `msquic.dll` 和 VC++ 运行库 DLL（`msvcp140.dll`、`vcruntime140.dll`、`vcruntime140_1.dll`）放在 exe 旁边。自己编译的是开发版，不带更新功能。

## 发布新版本（维护者）

**一次性设置**：用 `build\p2proxy-sign.exe genkey` 生成签名密钥，在 GitHub 仓库的 Settings → Secrets and variables → Actions 里，把私钥存为 secret `UPDATE_SIGNING_KEY`，公钥存为 variable `UPDATE_PUBLIC_KEY`。私钥另外备份到密码管理器：丢了以后，已安装的程序就无法再自动更新了。（v1 用 Go 工具生成的密钥可以继续使用，`p2proxy-sign pubkey` 能算出私钥对应的公钥。）

**每次发布**：

```
git tag v2.1.0
git push origin v2.1.0
```

GitHub Actions（`.github/workflows/release-v2.yml`）会编译、打包，并发布：

- `p2proxy-v2.x.x-windows-x64.zip`：给新用户下载；
- `p2proxy.exe`、`msquic.dll` 和三个运行库 DLL：自动更新用；
- `checksums.txt` 和签名 `checksums.txt.sig`。

可以用 `p2proxy-sign verify -tag v2.x.x checksums.txt 公钥` 检查某次发布的签名。
