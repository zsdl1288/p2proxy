# p2proxy：A 通过 B 的网络上网（点对点，无需服务器）

> **新版 v2（C++ 桌面版）在 [`cpp/`](cpp/README.md)**：一个程序两种角色（服务端/客户端），窗口界面，输入密钥即连接，自动生成 Clash 订阅地址。下面是 v1（Go 版）的说明。

```
  A 电脑（用 B 的网络）                                      B 电脑（出口）
 ┌──────────────────────────┐                           ┌──────────────────────┐
 │ 所有程序                  │                           │                      │
 │   ↓  Clash TUN 全局接管    │   UDP 打洞 + QUIC 加密隧道  │  p2proxy server      │
 │ p2proxy client :1080 ─────┼──────────────────────────→│    ↓                 │
 │ 控制面板 :1090            │  （A、B 之间直连，不经第三方）│  从 B 的网络访问互联网 │
 └──────────────────────────┘                           └──────────────────────┘
          ↑ 建立连接时交换双方地址（加密，经 ntfy.sh）↑
```

- **点对点直连**：两边都在路由器后面也能连。用 STUN 获取公网地址，双方同时向对方发包"打洞"。如果有公网 IPv6，会优先尝试 IPv6。
- **加密与认证**：隧道是 QUIC（TLS 1.3）。双方用同一个密钥派生出身份，密钥不对的机器连不上 B。
- **不需要服务器**：只在建立连接时，用免费的 ntfy.sh 交换一下双方的 IP 和端口。消息用密钥加密，ntfy.sh 只能看到一串密文。实际上网流量不经过 ntfy.sh。
- **TCP 和 UDP 都支持**：A 本地开放一个 SOCKS5（含 UDP）/HTTP 混合代理端口 `127.0.0.1:1080`。
- **断线不直连**：配合 Clash TUN，隧道断开时 A 直接断网，不会偷偷改走本地网络。
- **控制面板**：浏览器打开 http://127.0.0.1:1090 ，可以查看连接状态、测速、一键更新 A 和 B。

## 文件

| 文件 | 用途 |
|---|---|
| `p2proxy.exe` | 程序本体，A 和 B 用同一个文件 |
| `start-server.bat` | B 上双击运行（崩溃或更新后自动重启） |
| `start-client.bat` | A 上双击运行（崩溃或更新后自动重启） |
| `clash-A.yaml` | A 上 Clash 的配置：全局走 B，隧道断开就断网 |
| `*.go`、`ui.html` | 源代码（`ui.html` 是控制面板，会编译进程序） |
| `tools/sign` | 发布时给安装包签名的工具 |
| `.github/workflows/release.yml` | 推送版本标签后自动编译、签名、发布 |

## 安装与使用

### 第一步：生成密钥

从 GitHub Releases 下载 `p2proxy-windows-amd64.zip` 并解压。在任意一台电脑上，用**命令提示符 (cmd)** 进入解压后的文件夹，运行：

```
p2proxy.exe genkey > key.txt
```

这个文件夹留在 B 上。A 只需要知道 `key.txt` 里的那一行内容（第三步会在控制面板里粘贴），两边必须是同一个密钥。
**密钥等于访问 B 网络的钥匙**，请用安全的方式传输，不要公开，也不要提交到 Git。

### 第二步：B（出口机）

双击 `start-server.bat`。第一次运行时 Windows 防火墙会弹窗，选择**允许**。看到下面这样的日志就说明在等待连接了：

```
p2proxy v1.0.0 exit node listening on UDP port 40400
waiting for clients via https://ntfy.sh
this node can be reached at: <B的公网IP>:40400, 192.168.x.x:40400
```

**这个命令行窗口要一直开着**（可以最小化），关掉窗口 B 就停止了。B 也必须一直开机、不能睡眠（设置 → 系统 → 电源 → 睡眠：从不）。

**开机自启**（可选，以管理员身份在 cmd 里运行一次，路径换成你的实际路径）：

```
schtasks /Create /TN p2proxy-server /SC ONSTART /RU SYSTEM /RL HIGHEST /TR "C:\p2proxy\start-server.bat"
```

### 第三步：A

1. 下载并解压同一个 zip，**双击 `p2proxy.exe`**。浏览器会自动打开控制面板 http://127.0.0.1:1090 。
2. 第一次使用时，面板顶部会显示"设置密钥"：把 B 上 `key.txt` 的内容粘贴进去，点"保存并连接"。密钥会保存到 A 的 `key.txt`，以后双击就会直接连接。
3. 状态显示"已连接"就说明隧道通了。命令行窗口同样要保持打开（可以最小化）。想要崩溃或更新后自动重启，可以改用双击 `start-client.bat`。
4. 先不开 Clash，单独测一下（cmd 里运行）。返回的应该是 **B 的公网 IP**：
   ```
   curl -x socks5h://127.0.0.1:1080 https://api.ipify.org
   ```

### 第四步：A 全局走 B，断线就断网（配合 Clash）

p2proxy 只负责隧道。要让 A 上**所有程序**（包括不认系统代理的程序）都走 B，需要 Clash 的 TUN（虚拟网卡）模式来接管全部流量。推荐 **Clash Verge Rev**（mihomo 内核）。

1. 安装 Clash Verge Rev，在"设置"里安装**服务模式**（TUN 模式需要它）。
2. "订阅" → 新建 → 类型选**本地**，导入 `clash-A.yaml`，并选中这份配置。
3. "设置"里：
   - 打开**虚拟网卡模式 (TUN)**，并打开**严格路由 (strict-route)**；
   - 关闭 **DNS 覆写**，让配置里的 DNS 设置生效；
   - **系统代理**可以不开（有 TUN 就够了）；
   - 打开**开机自启**。
4. "代理"页面里模式保持**规则 (Rule)**，**不要切换成直连 (Direct)**。

`clash-A.yaml` 的规则只有两条：`p2proxy.exe` 自己的流量直连（它要用来连接 B），其余**全部**走 P2P。没有任何回落到直连的规则，所以：

- 隧道正常时：浏览器打开 https://api.ipify.org 显示 B 的 IP。
- 隧道断开时：所有网站都打不开（p2proxy 会直接拒绝请求，大约 15 秒后报错），**不会**偷偷改走 A 本地的网络。
- DNS：程序拿到的是 Clash 分配的假 IP，真正的域名交给 B 去解析，A 本地不向运营商发 DNS 查询。

**自检**：拔掉 B 的网线，或在 B 上关掉 p2proxy，A 应该立刻上不了网；恢复后 A 会自动重连。

## 控制面板与测速

A 上 client 运行时，浏览器打开 http://127.0.0.1:1090 （只能本机访问）。也可以在 cmd 里运行 `p2proxy speedtest`。

测速会分段测，用来判断瓶颈在哪：

| 项目 | 测的是什么 |
|---|---|
| 隧道下载 (B→A) | B 的上传带宽 + A 的下载带宽 + 两地之间的线路。**A 上网下载的上限通常就是这个数** |
| 隧道上传 (A→B) | A 的上传带宽 + B 的下载带宽 |
| 经 B 上网 · 下载 | A 经 B 下载一个外网文件，也就是 A 实际能拿到的速度 |
| 延迟 · 上行丢包 | 隧道的往返时间，以及测速期间 A 发出的包有多少丢失 |

"经 B 上网"这一项需要一个允许下载的大文件地址，例如你自己服务器上的文件。启动客户端时指定：

```
p2proxy.exe client -speed-url https://你的服务器/100MB.bin
```

不指定时只测隧道。

**提速建议**：

- A 下载的数据都要从 B **上传**过来，所以 B 的上行带宽决定了 A 的下载上限。B 如果是上下行不对称的宽带（例如有线电视宽带上行只有 30–50 Mbps），换成光纤对称宽带效果最明显。
- 如果测速显示丢包超过 1%，可以试试多条并行连接：在 `start-client.bat` 里把 `p2proxy.exe client` 改成 `p2proxy.exe client -conns 4`。
- 本机测试时，隧道本身可以跑到 1.5 Gbps 以上，一般不会成为瓶颈。

## 软件更新

- **A 一键更新**：有新版本时，控制面板会显示"更新到 vX"按钮，点击后自动下载、校验、替换并重启（约断网 5 秒）。也可以运行 `p2proxy update`。
- **远程更新 B**：控制面板里点"出口节点 (B)"的更新按钮，B 会自己下载新版本并重启，不需要去 B 那台电脑上操作。也可以运行 `p2proxy update -node`。
- **自动检查**：A 每 6 小时检查一次 GitHub 上的最新版本，日志和控制面板里都会提示。
- **安全**：每个版本的校验文件都用发布者的私钥签名，程序内置对应的公钥。安装包被篡改、校验文件被改、拿旧版本冒充新版本，都会被拒绝安装。
- A 检查和下载更新的流量同样走隧道，不会直连。
- 通过 `start-*.bat` 启动时，更新后由脚本自动重启；直接运行 exe 时，程序会自己启动新版本。

## 稳定性设计

- **快速发现断线**：每 5 秒保活一次，20 秒没有响应就判定断开并重连。
- **B 重启后立即重连**：B 启动时会发一条 hello 通知；A 收到后立刻放弃旧连接、重新连接，不用等超时。
- **短暂断网后快速恢复**：A 复用同一个 UDP 端口，并先直连上次成功的 B 地址，大多数情况下几秒内恢复，而且不消耗信令。
- **网络切换**：A 从 Wi-Fi 换到网线等情况，会自动换到新网卡重新连接。
- **节省信令额度**：ntfy.sh 对免费用户每天的消息数有限制，所以连不上时重试间隔会逐渐拉长（最长 5 分钟）。不过 B 一上线（hello），或 A 的网络一恢复，就会立刻重试。

### p2proxy 自己的流量怎么办？

A 上 p2proxy 连接 B 的流量（打洞、QUIC 隧道、ntfy 信令）当然必须从 A 本地网络出去，这是隧道本身。为了不被 Clash 的 TUN 再抓回来造成死循环，p2proxy 默认 `-iface auto`：

- 自动找到真实的物理网卡（以太网 / Wi-Fi），把自己的 socket 绑到这块网卡上，用的是 Clash 自己同样采用的 `IP_UNICAST_IF` 机制；
- 自己查域名时走 DNS-over-TLS（1.1.1.1 / 8.8.8.8 的 853 端口），不受 Clash fake-ip 和严格路由影响，运营商也看不到查了什么。

如果自动选错了网卡，可以手动指定，例如 `p2proxy.exe client -iface "Wi-Fi"`。

## 连不上（打洞失败）怎么办

B 上 p2proxy 启动时会做 STUN 检测。如果日志出现 `symmetric NAT`，或者 A 一直显示 `no candidate reachable`，说明两边的 NAT 类型不适合打洞（例如运营商级 NAT、手机热点）。可以按顺序尝试：

1. **B 的路由器做端口转发**：把 UDP 40400 转发到 B 的内网 IP。之后打洞失败时，A 也能直接连到 B。如果 B 的公网 IP 会变，可以配合 DDNS，并在 B 上加 `-advertise 你的DDNS域名:40400`。
2. **用 IPv6**：加拿大的 Rogers、Bell、Telus、Videotron 大多支持 IPv6。如果两边都有公网 IPv6，p2proxy 会自动尝试。用 IPv6 时需要在 B 的防火墙里放行 p2proxy（第一次运行的弹窗点"允许"）。
3. **跳过信令直接连接**：如果 B 有固定可达的地址，A 可以用 `p2proxy.exe client -peer B的地址:40400`。

## 安全说明

- 只有持有同一个密钥的机器才能通过 B 上网，也只有它们能让 B 更新。密钥泄露后，用 `genkey` 重新生成，并替换两边的 `key.txt`。
- ntfy.sh 能看到的只有：一个随机的主题名、加密后的数据、以及你的 IP 访问过 ntfy.sh。如果不想依赖它，可以自建 ntfy，然后两边都加上 `-signal https://你的ntfy服务器`。
- 控制面板只接受来自本机、且由面板页面自己发出的请求，其他网站无法通过浏览器操作它。
- A 通过隧道能访问 B 所在的局域网（例如 B 家的路由器后台），这是正常现象。

## 已知限制

- **Clash 本身退出或崩溃时**，系统会恢复原来的路由，A 会变成直连上网。p2proxy 隧道断开时会断网，但 Clash 进程消失这种情况它管不了。对策是 Clash Verge Rev 用服务模式并开机自启。如果需要"Clash 不在也绝不直连"，要再加一层 Windows 防火墙（WFP）级别的断网保护，目前还没有实现。
- 和 A 在同一局域网内的设备（打印机、路由器后台）仍走本地，不经过 B。这部分不是互联网流量。
- ping（ICMP）不会经过隧道。
- 两边都是对称 NAT、又都没有端口转发和 IPv6 时无法打洞。这个程序没有中转服务器。
- A 和 B 的版本最好保持一致：用控制面板先更新 B，再更新 A。

## 发布新版本（维护者）

### 一次性设置

1. 在本地生成签名密钥（只做一次，**私钥绝不能泄露或提交**）：
   ```
   go run ./tools/sign genkey
   ```
2. 在 GitHub 仓库的 Settings → Secrets and variables → Actions 里：
   - **Secrets** 新建 `UPDATE_SIGNING_KEY`，填 private 那一行的值；
   - **Variables** 新建 `UPDATE_PUBLIC_KEY`，填 public 那一行的值。
3. 私钥另外备份到密码管理器。私钥丢失后，已发布的旧版本将无法再自动更新，只能让用户手动下载一次新版本。

### 每次发布

```
git tag v1.0.0
git push origin v1.0.0
```

GitHub Actions 会自动：编译 Windows / macOS / Linux（amd64、arm64）版本，打包 Windows 压缩包（含 bat、Clash 配置和本说明），生成并签名 `checksums.txt`，创建 Release。用户的客户端会在 6 小时内发现新版本，也可以在控制面板点"检查更新"。

版本号必须是 `v主版本.次版本.修订号` 格式。只有正式 Release 会被检测到，草稿和预发布版本不会。

### 从源码编译

```
go build -trimpath -ldflags "-s -w" -o p2proxy.exe .
```

需要 Go 1.27 或更高版本（见 go.mod）。自己编译的版本是开发版，不带更新功能。`-iface` 网卡绑定功能目前只支持 Windows。
